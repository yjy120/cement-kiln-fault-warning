水泥窑线故障预警系统 —— 队友上手说明

我们的规矩：日常干活都在 dev 分支，main 是稳定版，只有 owner 能合并到 main。

【一、第一次准备，只做一次】
（下面版本是 2026-11-24 查的；以后以官网标注为准，认准 LTS 就行）

1. 装 Node.js：浏览器打开 https://nodejs.org/ ，下载 LTS 版，一路"下一步"装完。
   当前 LTS：v26.13.1（自带 npm 11.20.0），别下成 Current / Alpha。
   Windows 64 位直链：https://nodejs.org/dist/v26.13.1/node-v26.13.1-x64.msi

2. 装 Git：打开 https://git-scm.com/install/windows ，下载安装，一路下一步。
   当前最新版：2.56.1
   Windows 64 位直链：https://github.com/git-for-windows/git/releases/download/v2.56.1.windows.1/Git-2.56.1-64-bit.exe

3. 找个文件夹放项目，比如 D 盘建个 cement 文件夹，
   在里面空白处按住 Shift + 鼠标右键 → "在此处打开 PowerShell / 终端"。
4. 输入这条，把项目拉下来（仓库是公开的，这步不会要账号密码）：
   git clone https://github.com/yjy120/cement-kiln-fault-warning.git
5. 进入下载出来的文件夹：
   cd cement-kiln-fault-warning
6. 切到 dev 分支（我们日常干活的分支）：
   git checkout dev
7. 双击「一键安装依赖.bat」，黑窗口跑完（出现 Done）就好。
8. 双击「一键启动.bat」，浏览器自动打开页面 → 项目跑起来了。

【补充：push 时才会用到的"令牌"（每人自己弄一个）】
- 令牌 = GitHub 个人访问密钥（Personal Access Token，PAT），不是 GitHub 登录密码。
- 拉代码（clone / pull）不用令牌，仓库是公开的；只有上传（git push）时才会问。
- 每个人自己生成，别共用，也别发群里。

生成步骤（一步一步点）：
1. 浏览器打开 https://github.com/settings/tokens （没登录先登录自己的 GitHub 账号）
2. 点 Generate new token → Generate new token (classic)
   —— 必须选 classic（经典版）。新版那个 Fine-grained tokens 对咱们这个仓库用不了：
      仓库是个人账号下的，你们是被加成协作者的，细粒度令牌推不上去。
3. Note 那栏填 cement
4. Expiration 选 90 天
5. 权限只勾 repo 这一项（勾上它，下面子项会自动全勾），别的都别勾
6. 拉到最下面点 Generate token
7. 复制那串 ghp_ 开头的内容，存到自己备忘录 / 记事本里
   —— 这串只显示这一次，关掉页面就再也看不到了，丢了只能重新生成

push 的时候怎么用：
- 在项目文件夹的终端里执行 git push origin dev
- 弹出登录框：Username 填自己的 GitHub 用户名，Password 那栏粘贴令牌（不是登录密码）
- 看到 "dev -> dev" 就成了

之前 push 失败过、弹的是旧密码报错（或者输对了还让重输）：
- 开始菜单搜"凭据管理器"打开 → Windows 凭据 → 普通凭据
- 找到 git:https://github.com 这一条，点开 → 删除
- 回到终端重新 git push origin dev，再输一次用户名和令牌

- owner 得先把你的 GitHub 用户名加成协作者，不然有令牌也推不上去。
- 令牌别发群里，谁的就谁自己用。

【补充：智能助手的 AI Key（要用 AI 问答才配，不配不影响其他页面）】
- 项目右下角有个"智能助手"，能问答本系统相关问题，走的是硅基流动的大模型接口。
- 每人自己申请 key：注册 https://cloud.siliconflow.cn ，控制台 → API 密钥 → 新建密钥，复制保存。
- 在项目根目录找到 .env.local.example，复制一份改名为 .env.local，
  把里面的"在这里填你的key"换成你自己的 key（开头是 sk-）。
- 改完要重启项目（关掉黑窗口重新双击"一键启动.bat"）才生效。
- .env.local 不会上传到 GitHub（已在 .gitignore 里），不用担心泄露；但也别发给别人。
- 没配 key 的话，页面和 AI 图标都在，只是点了提问会提示调用失败，其他功能正常。

【二、以后每次干活就三步】

第 1 步：在项目文件夹里打开终端，先拉代码
   VS Code 里按 Ctrl + ` 打开终端，或者在文件夹空白处右键"在终端中打开"，然后敲：

     git checkout dev
     git pull origin dev

   —— 把别人改的代码拉到你电脑。每次动手前先做，必做！

第 2 步：改代码
   —— 用 VS Code 打开 cement-kiln-fault-warning 文件夹，
      只改分给你的那几个文件，别动别人的。

第 3 步：改完上传（存好 + 传到 GitHub）
   在终端里依次敲这三行，每行敲完按回车：

     git add .
     git commit -m "这次改了啥"
     git push origin dev

   —— 引号里写你具体干了啥，比如 "改了首页图表"。
   —— 看到 "dev -> dev" 就成了。千万别写 main！

【三、必须记住的规矩】
1. 只往 dev 推：git push origin dev  —— 千万别写 main！main 是稳定版，只有 owner 能合。
2. 动手前先 pull，改完立刻 add → commit → push，别攒着。
3. 各改各的文件，别俩人同时改一个，不然会"冲突"（报错截图发群）。
4. 推之前先确认 GitHub 网页能打开；如果连不上或报 SSL 错，再开代理/VPN 重试。

【四、常用命令】
git status              看现在改了哪些文件
git pull origin dev     拉最新代码
git add .               暂存所有改动
git commit -m "说明"    提交改动
git push origin dev     推到 dev 分支
git checkout dev        切换到 dev 分支
git log --oneline       看提交记录

【五、报错怎么办】
- 提示没权限（403 / permission denied）：两种可能——
  ① 你还没被加成协作者，把 GitHub 用户名发群里，owner 加你之后就能推了；
  ② 令牌生成成了 Fine-grained（新版细粒度），这个仓库用不了，按上面步骤重新生成 classic 版。
- 提示 SSL / SSL_read / connection reset：在终端先敲这一条（只需一次）：
  git config --global http.sslBackend openssl
  然后再重新 push。
- 任何看不懂的红色报错：黑窗口截图发群，owner 帮你看。

有问题群里直接问，看到就回。
